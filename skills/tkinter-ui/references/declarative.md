# Declarative TkUI workflow (Mode B)

Use this when the interface is multi-page, form/table-heavy, must preview as both
`web` and `win11`, or is generated by an AI from a description.

## Components of the workflow

1. Write `app.json` (style-neutral).
2. Validate it.
3. Run with `--style web` or `--style win11`.
4. Add Python actions only when business logic is required.

The bundled runtime is `runtime/tkui`; `scripts/use_tkui.py` finds it
automatically. `references/spec.md` is the field reference; `components.md` is the
catalog.

## Commands

From the skill directory:

```bash
python scripts/use_tkui.py catalog
python scripts/use_tkui.py catalog --markdown
python scripts/use_tkui.py check app.json --json
python scripts/use_tkui.py run app.json --style web
python scripts/use_tkui.py run app.json --style win11
python scripts/use_tkui.py demo --choose
```

If the runtime is elsewhere:

```bash
set TKUI_HOME=D:\path\to\tkui        # Windows
export TKUI_HOME=/path/to/tkui       # Unix
python <skill>/scripts/use_tkui.py check app.json
```

The upstream libraries must be importable too: either installed, placed as
`tkwebui` / `tkwin11` packages, or pointed to with
`TKUI_TKWEBUI_PATH` / `TKUI_TKWIN11_PATH`.

## Output contract

The model must output a single JSON object:

```json
{
  "version": 1,
  "title": "Window title",
  "window": {"size": [1000, 700]},
  "body": {"type": "column", "children": []}
}
```

Rules:

- `version: 1`;
- `body` or `pages`;
- every node has `type`;
- `children` only on containers;
- `id` unique;
- enum values from the catalog;
- actions are strings, built-in objects, or lists;
- no Tk code, colors, fonts, or `web`/`win11` branches.

`python scripts/use_tkui.py check app.json --json` returns:

```json
{
  "ok": false,
  "issues": [
    {"path": "$.body.children[0].type", "level": "error",
     "message": "未知组件 'buton'，是否想写 'button'？"}
  ],
  "actions": ["save"]
}
```

Fix by `path`, then re-run until `ok: true`.

## Style selection

The same spec works in both styles:

```bash
python scripts/use_tkui.py run app.json --style web
python scripts/use_tkui.py run app.json --style win11
```

At application start:

```python
import tkui

style = tkui.choose_style()       # "web" or "win11", persisted
app = tkui.App("app.json", style=style)
app.run()
```

At runtime:

```python
app.restart_in_style("win11")
```

The process must restart because the upstream theme libraries cannot coexist in
one Tk interpreter.

## Python bridge

```python
import sys
sys.path.insert(0, r"<skill>/runtime")   # or pip install the tkui package
import tkui

def on_save(event):
    name = event.app.get("name")
    event.app.notify(f"Saved {name}", kind="success")

app = tkui.App("app.json", actions={"save": on_save})
app.run()
```

Event fields: `name`, `value`, `id`, `widget`, `app`. Callbacks may take zero or
one argument.

Value access:

```python
app.get("name")
app.set("name", "new value")
app.set("name", "silent", silent=True)
app.native("tasks").insert_row(["New", "Mia", "To do"])
app.navigate("settings")
```

## Actions

### Built-in actions (pure JSON)

```json
{"action": "notify", "message": "Saved", "kind": "success"}
{"action": "navigate", "page": "settings"}
{"action": "set", "target": "name", "value": "new"}
{"action": "toggle", "target": "autosave"}
{"action": "dialog", "message": "Continue?", "title": "Confirm"}
{"action": "style", "style": "win11"}
{"action": "chain", "chain": [{"action": "notify", "message": "One"},
                              {"action": "navigate", "page": "home"}]}
{"action": "quit"}
```

`"$value"` inserts the event value:

```json
{"type": "segmented", "options": ["web", "win11"],
 "command": {"action": "style", "style": "$value"}}
```

### Named actions (Python)

Spec:

```json
{"type": "button", "text": "Save", "command": "save"}
```

Python:

```python
app = tkui.App(spec, actions={"save": on_save})
```

Use built-in actions for prototypes; use named actions for persistence, network,
or validation logic.

## Anti-patterns

| Do not | Why |
| --- | --- |
| Write `Tk`/`ttk` calls inside a spec | Specs are data, not code |
| Set `bg`, `fg`, or font sizes | Breaks one-look consistency |
| Use pixels for layout | Use `fill`, `expand`, `grid`, `gap` |
| Add ids to every node | Only for read/update targets |
| Use a component not in the catalog | Validate fails or produces nothing |
| Ignore `ok: false` | Fix by JSON path |
| Mix `tkwebui` and `tkwin11` imports | Upstream incompatibility |

## Extending the runtime

Add a component in four places:

1. `runtime/tkui/catalog.py` — metadata and schema source;
2. `runtime/tkui/renderer.py` — renderer + `_RENDERERS`;
3. `skills/tkinter-ui/tests` or the repo's `tests/_render_all.py` — render both styles;
4. regenerate `schema/tkui-1.json`, `references/components.md`, and this catalog.

Run the skill self-test after changes:

```bash
python scripts/selftest.py
```
